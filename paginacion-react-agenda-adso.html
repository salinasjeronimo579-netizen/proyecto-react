Tema de aprendizaje: Paginación en React — Agenda ADSO

Con búsqueda y orden, la Agenda ADSO ya se ve profesional — pero si crece a 50 o 200 contactos, mostrarlos todos de una vez vuelve a ser un problema. Hoy dividimos la lista en páginas, con estado y matemática simple.

Tema: Paginación de listas Extensión de Agenda ADSO v8/v9 useState + slice + Math.ceil
00

Propósito y resultados de aprendizaje

Que el aprendiz implemente paginación sobre una lista de datos en React, dividiendo resultados extensos en páginas navegables, sin romper la búsqueda ni el ordenamiento ya construidos.

01

¿Por qué paginar?

Renderizar 200 tarjetas de contacto a la vez es lento para el navegador y agotador para la persona que tiene que hacer scroll. La paginación resuelve ambos problemas: solo se pinta un pedazo de la lista a la vez.

  • Rendimiento: React solo crea los nodos del DOM para los contactos visibles.
  • Usabilidad: es más fácil orientarse en "página 2 de 5" que en un scroll infinito sin referencia.
  • Costo real: si los datos vinieran paginados desde el backend, además ahorrarías ancho de banda — aquí lo hacemos en el cliente, sobre datos que ya tenemos.
02

Dos estados nuevos

Igual que busqueda y ordenAsc en la Clase 10, la paginación vive en su propio par de estados — no tocan los datos, solo cómo se muestran.

src/App.jsx
// Página que se está mostrando ahora mismo (empieza en 1)
const [paginaActual, setPaginaActual] = useState(1);

// Cuántos contactos mostrar por página
const [contactosPorPagina] = useState(3);
paginaActual empieza en 1
No en 0 — así "página 1" coincide con lo que la persona espera ver, sin restar mentalmente.
contactosPorPagina
Aquí es un valor fijo, pero nada impide convertirlo en configurable (lo hacemos en el mini reto de más abajo).
03

Calcular el total de páginas

Con la lista ya filtrada y ordenada (de la Clase 10), calculamos cuántas páginas hacen falta.

src/App.jsx
const totalPaginas = Math.ceil(
  contactosOrdenados.length / contactosPorPagina
);
Math.ceil(...)
Redondea siempre hacia arriba: con 7 contactos y 3 por página, 7 / 3 = 2.33 → Math.ceil da 3 páginas, para que el séptimo contacto no se quede sin página.
Se recalcula solo
Como no es estado, cambia automáticamente si contactosOrdenados cambia — por ejemplo, al escribir en el buscador y reducir los resultados.
04

Recortar la página actual con slice()

De toda la lista ordenada, solo tomamos el pedazo que corresponde a la página en la que estamos.

src/App.jsx
const indiceInicio = (paginaActual - 1) * contactosPorPagina;
const indiceFin = indiceInicio + contactosPorPagina;

const contactosPaginados = contactosOrdenados.slice(
  indiceInicio,
  indiceFin
);
(paginaActual - 1) * contactosPorPagina
Con página 1 y 3 por página: (1-1)*3 = 0 — empieza en el índice 0. Con página 2: (2-1)*3 = 3 — empieza en el cuarto contacto (índice 3).
.slice(inicio, fin)
Igual que .filter() y .sort(), .slice() no modifica el arreglo original — devuelve un pedazo nuevo. fin no es inclusivo, así que sirve pasarlo directo.
Este es el único paso nuevo de verdad: todo lo demás (búsqueda, orden) sigue igual que en la Clase 10 — la paginación se aplica después, sobre contactosOrdenados.
05

Controles: Anterior, Siguiente y números de página

Un botón "Anterior", uno por cada número de página, y "Siguiente" — deshabilitados en los extremos.

JSX del paginador
<div className="flex items-center justify-center gap-2 mt-4">
  <button
    disabled={paginaActual === 1}
    onClick={() => setPaginaActual((p) => p - 1)}
  >
    ← Anterior
  </button>

  {Array.from({ length: totalPaginas }, (_, i) => i + 1).map((n) => (
    <button
      key={n}
      className={n === paginaActual ? "activo" : ""}
      onClick={() => setPaginaActual(n)}
    >
      {n}
    </button>
  ))}

  <button
    disabled={paginaActual === totalPaginas}
    onClick={() => setPaginaActual((p) => p + 1)}
  >
    Siguiente →
  </button>
</div>
Array.from({'{ length: totalPaginas }'}, (_, i) => i + 1)
Un truco común para generar [1, 2, 3, ..., totalPaginas] sin un bucle for — creamos un array "vacío" del tamaño correcto y lo llenamos con el índice + 1.
disabled={'{paginaActual === 1}'}
"Anterior" se desactiva solo en la primera página; "Siguiente", solo en la última — sin necesitar lógica extra.
setPaginaActual((p) => p - 1)
La forma funcional, igual que con ordenAsc: parte del valor anterior en vez de asumirlo.
06

Reiniciar a la página 1 cuando cambia la búsqueda

Si estás en la página 4 y escribes algo que reduce los resultados a 2, la página 4 ya no existe. Hay que volver a la 1.

src/App.jsx
useEffect(() => {
  setPaginaActual(1);
}, [busqueda, ordenAsc]);
[busqueda, ordenAsc] como dependencias
Cada vez que cambia lo que se busca (o el orden), volvemos a la primera página — evita quedarte viendo una página vacía o inexistente.
¿Por qué no [contactosOrdenados]?
Ese array cambia en cada render (es un valor nuevo cada vez, aunque el contenido sea igual) — usarlo como dependencia reiniciaría la página en cada tecla incluso sin razón. Por eso se usan las causas reales: busqueda y ordenAsc.
